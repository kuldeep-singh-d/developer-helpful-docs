# Contributing

Contributions that improve accuracy, clarity, safety, or practical usefulness are welcome.

## Before writing

1. Search existing guides to avoid duplication.
2. Keep each file focused on one technology or workflow.
3. Use lowercase filenames with hyphens.
4. Never include credentials, private URLs, personal data, or client-sensitive information.

## Documentation expectations

- Explain commands with comments.
- Include a use case for important workflows.
- Put least-destructive troubleshooting steps first.
- Add a clear warning before deleting data, caches, applications, builds, or device state.
- Use realistic placeholders such as `com.example.app` and `DEVICE_ID`.

## Pull request checklist

- Verify every command against current official documentation or a safe local test.
- Check Markdown links and formatting.
- Review the diff for unrelated or sensitive content.
- Use a clear title and explain what was verified.

See [GitHub Pull Request Workflow](github/github-pull-request-workflow.md) for an example.
